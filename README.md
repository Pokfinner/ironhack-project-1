# Multi-Stack Voting App on AWS — Terraform & Ansible

A microservices voting app (cats 🐱 vs. dogs 🐶), containerized with Docker and deployed to AWS. The infrastructure is built with **Terraform**, the containers are deployed with **Ansible**, and users reach the app through an **Application Load Balancer**.

> Project 1 of the Ironhack DevOps & Cloud Computing bootcamp.

## Tech stack

- **Docker** — own images on DockerHub (`hserindik/vote`, `hserindik/result`, `hserindik/worker`)
- **Terraform** — VPC, public and private subnets in two AZs, Internet Gateway, NAT Gateway, route tables, security groups, EC2, Application Load Balancer
- **Terraform remote state** — S3 bucket (versioned, private) + DynamoDB state locking
- **Ansible** — installs Docker and deploys all containers, idempotent playbooks. The inventory is generated by Terraform

## Security

- **All app servers are in private subnets** without public IPs. They reach the internet only through the NAT Gateway.
- Only two things are public: the **ALB** (port 80) and the **bastion host** (SSH, only from my IP).
- **Security groups** reference each other (least privilege):
  - ALB: port 80 from the internet
  - A: ports 8080/8081 only from the ALB, SSH only from the bastion
  - B: Redis (6379) only from A, SSH only from the bastion
  - C: PostgreSQL (5432) only from A and B, SSH only from the bastion
- Ansible connects to all servers **through the bastion** (SSH ProxyCommand).

## Load balancer routing

| Request | Target |
|---|---|
| `/vote`, `/vote/*` | Vote |
| `/static/*` | Vote (its CSS) |
| `POST /` | Vote (the voting form) |
| `/result`, `/result/*` | Result |
| anything else | 404 |

**Why the extra rules?** Vote uses absolute paths (`/static/...`) and posts its form to `/`. Result uses relative paths, so it works under `/result/` without changes. I chose **explicit rules** instead of a catch-all rule, so that unknown requests return a 404 and don't silently go to Vote.

## How to build the images

```bash
docker login -u hserindik   # only once, use an access token as password
./build.sh                  # builds and pushes with tags: latest, v1
./build.sh v2               # builds and pushes with tags: latest, v2
```

## How to deploy

**Prerequisites:** AWS CLI, Terraform, Ansible (with `community.docker`), an SSH key at `~/.ssh/voting-app-key`.

```bash
# 1. Remote state (only once)
cd terraform/backend-setup && terraform init && terraform apply

# 2. Infrastructure — also generates the Ansible inventory and group_vars
cd ../infra
echo 'my_ip = "<YOUR_IP>/32"' > terraform.tfvars
terraform init && terraform apply

# 3. Deploy all containers
cd ../../ansible && ansible-playbook site.yml
```

Open `http://<alb_dns_name>/vote` to vote and `http://<alb_dns_name>/result` to see the results.

**Clean up:** `cd terraform/infra && terraform destroy`

## Notes

- The `votes` table has no UNIQUE constraint on the voter ID, so one browser can vote many times. This makes demos easier.
